## ⚡ Competitive Programming Concept: Longest Increasing Subsequence (LIS)

**Category:** DP
**TL;DR:** Mencari subsekuens terpanjang dalam sebuah array di mana setiap elemen lebih besar dari elemen sebelumnya, menggunakan optimasi O(N log N).

Longest Increasing Subsequence (LIS) adalah masalah klasik dalam pemrograman kompetitif yang meminta kita untuk menemukan panjang subsekuens terpanjang dari sebuah array atau sekuens yang diberikan, di mana elemen-elemen dalam subsekuens tersebut tersusun secara strictly increasing (setiap elemen lebih besar dari elemen sebelumnya).

Salah satu pendekatan efisien untuk menyelesaikan LIS adalah dengan menggunakan algoritma berbasis 'patience sorting' yang berjalan dalam waktu O(N log N). Algoritma ini menggunakan sebuah array pembantu, sebut saja `tails`, di mana `tails[i]` menyimpan elemen terkecil yang merupakan *akhir* dari semua subsekuens yang meningkat (increasing subsequence) dengan panjang `i+1`. Array `tails` ini akan selalu terurut secara strictly increasing.

Ketika kita mengiterasi melalui setiap angka `num` dalam array input: jika `num` lebih besar dari semua elemen di `tails`, artinya `num` dapat memperpanjang LIS terpanjang yang ada saat ini, jadi kita tambahkan `num` ke akhir `tails`. Namun, jika `num` tidak lebih besar dari semua elemen di `tails`, kita mencari posisi yang tepat di `tails` di mana `num` dapat menggantikan sebuah elemen. Lebih spesifiknya, kita mencari elemen pertama di `tails` yang lebih besar atau sama dengan `num` menggunakan binary search (seperti `std::lower_bound`). Mengganti elemen ini dengan `num` tidak akan mengubah panjang LIS yang dapat dibentuk sampai saat ini, tetapi ia akan membentuk LIS dengan panjang yang sama namun dengan *nilai akhir* yang lebih kecil, yang mana ini lebih optimal karena memberikan peluang lebih besar untuk diperpanjang di kemudian hari oleh angka-angka yang lebih kecil.

Akhirnya, panjang array `tails` setelah memproses semua elemen akan menjadi panjang LIS dari array input. Kompleksitas waktu dari algoritma ini adalah O(N log N) karena setiap elemen dari N elemen input diproses sekali, dan setiap pemrosesan melibatkan operasi `lower_bound` pada array `tails` yang ukurannya maksimal N, membutuhkan waktu O(log N).

```
#include <vector>
#include <algorithm> // Untuk std::lower_bound

int longestIncreasingSubsequence(const std::vector<int>& arr) {
    if (arr.empty()) return 0;
    std::vector<int> tails;
    for (int num : arr) {
        auto it = std::lower_bound(tails.begin(), tails.end(), num);
        if (it == tails.end()) { // num lebih besar dari semua tails yang ada
            tails.push_back(num);
        } else { // num dapat menggantikan salah satu tail
            *it = num;
        }
    }
    return tails.size();
}
```

💡 **Fun Fact:** Algoritma LIS O(N log N) ini memiliki hubungan erat dengan 'patience sorting', sebuah algoritma pengurutan non-komparatif yang diinspirasi dari permainan kartu solitaire 'Patience'.
