## ⚡ Competitive Programming Concept: Dynamic Programming (DP) Dasar

**Category:** DP
**TL;DR:** Dynamic Programming adalah metode optimisasi untuk memecahkan masalah kompleks dengan memecahnya menjadi submasalah yang lebih kecil, menyimpan hasilnya, dan menggunakannya kembali untuk menghindari komputasi yang berulang.

Dynamic Programming (DP) adalah teknik algoritma yang sangat fundamental dan powerful dalam competitive programming. Prinsip utamanya adalah menyelesaikan masalah dengan membaginya menjadi submasalah yang tumpang tindih (overlapping subproblems) dan memiliki substruktur optimal (optimal substructure). Daripada menghitung ulang solusi untuk submasalah yang sama berkali-kali, DP menyimpan hasil komputasi submasalah tersebut, biasanya dalam sebuah array atau tabel, untuk digunakan di kemudian hari. Ini sering disebut sebagai 'memoization' (pendekatan top-down) atau 'tabulation' (pendekatan bottom-up).

Untuk menerapkan DP, kita perlu mendefinisikan 'state' (keadaan) dari masalah, yang biasanya direpresentasikan oleh indeks-indeks di tabel DP. Selanjutnya, kita merumuskan 'recurrence relation' (hubungan rekursif) yang menjelaskan bagaimana solusi untuk suatu state bergantung pada solusi state-state sebelumnya. Terakhir, kita menentukan 'base cases' (kasus dasar) yang merupakan kondisi awal atau paling sederhana yang solusinya sudah diketahui secara langsung tanpa perlu rekursi. Urutan komputasi sangat penting dalam DP; pastikan semua submasalah yang dibutuhkan untuk menyelesaikan suatu state sudah terkomputasi sebelumnya.

Contoh klasik DP adalah menghitung deret Fibonacci, mencari jalur terpendek dalam graph (misalnya Floyd-Warshall), atau masalah 'Coin Change' untuk mencari jumlah koin minimum. DP memungkinkan kita mengubah solusi rekursif yang bisa sangat lambat (misalnya, eksponensial) karena perhitungan berulang menjadi solusi polinomial yang jauh lebih efisien. Pemilihan state dan recurrence relation yang tepat adalah kunci keberhasilan dalam menyelesaikan soal-soal DP.

Kompleksitas waktu dan ruang dari algoritma DP biasanya ditentukan oleh jumlah state yang ada dan biaya komputasi untuk setiap state. Jika ada N state dan setiap state membutuhkan M operasi, maka kompleksitas waktu umumnya adalah O(N * M). Kompleksitas ruang biasanya O(N) untuk menyimpan semua state, meskipun terkadang bisa dioptimalkan menjadi O(M) atau O(1) jika solusi untuk suatu state hanya bergantung pada sejumlah kecil state sebelumnya (misalnya, pada deret Fibonacci, hanya butuh 2 state sebelumnya).

```
std::vector<int> dp(target + 1, target + 1);
dp[0] = 0; // 0 coins for 0 amount
for (int i = 1; i <= target; ++i) {
    for (int coin : coins) {
        if (i >= coin) {
            dp[i] = std::min(dp[i], 1 + dp[i - coin]);
        }
    }
}
// Result is dp[target], or -1 if dp[target] == target + 1
```

💡 **Fun Fact:** Penemu konsep Dynamic Programming, Richard Bellman, sengaja memilih nama 'Dynamic Programming' pada tahun 1950-an karena terdengar penting dan tidak terlalu teknis. Tujuannya adalah untuk menghindari pertanyaan atau intervensi yang tidak perlu dari atasannya di lembaga penelitian, yang mungkin tidak akan menyukai istilah yang terlalu matematis.
