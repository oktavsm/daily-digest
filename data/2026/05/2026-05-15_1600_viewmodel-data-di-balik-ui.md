## 🤖 Android Concept: ViewModel: Data di balik UI

**Category:** Architecture
**TL;DR:** ViewModel adalah komponen Jetpack yang dirancang untuk menyimpan dan mengelola data terkait UI dalam siklus hidup yang sadar akan konfigurasi perangkat, mencegah hilangnya data saat rotasi layar atau perubahan konfigurasi lainnya.

Saat mengembangkan aplikasi Android, salah satu tantangan umum adalah menjaga data atau state UI tetap utuh ketika perangkat mengalami perubahan konfigurasi, seperti rotasi layar. Secara default, Activity atau Fragment akan dihancurkan dan dibuat ulang, yang menyebabkan data yang belum disimpan akan hilang. Hal ini bisa mengganggu pengalaman pengguna, memaksa mereka untuk mengulang input atau proses dari awal.

ViewModel hadir sebagai solusi dari Android Jetpack Architecture Components untuk masalah ini. ViewModel dirancang untuk menyimpan dan mengelola data terkait UI dengan cara yang sadar akan siklus hidup. Ini berarti, ViewModel dapat bertahan melalui perubahan konfigurasi seperti rotasi layar atau perubahan bahasa, namun akan dibersihkan (dihancurkan) saat `LifecycleOwner` (misalnya Activity atau Fragment) yang terkait dengannya benar-benar selesai dan tidak lagi dibutuhkan.

Dengan menggunakan ViewModel, Anda dapat memisahkan secara jelas logika yang menangani persiapan dan penyimpanan data dari kode UI itu sendiri. Activity atau Fragment hanya perlu mengamati data dari ViewModel dan memperbarui tampilan, sementara ViewModel bertanggung jawab untuk menyediakan data tersebut. Pemisahan tanggung jawab ini tidak hanya mencegah hilangnya data tetapi juga membuat kode UI lebih ramping, lebih mudah dibaca, dan lebih mudah diuji, karena logika bisnis dapat diuji secara independen.

Seringkali, ViewModel dipasangkan dengan `LiveData` atau `StateFlow` untuk menyediakan data secara reaktif ke UI. `LiveData` adalah kelas data yang dapat diamati dan sadar akan siklus hidup, yang berarti ia hanya akan memperbarui observer (seperti UI Anda) ketika observer tersebut berada dalam keadaan aktif (misalnya `STARTED` atau `RESUMED`). Kombinasi ini sangat kuat untuk membangun aplikasi yang responsif, efisien dalam penggunaan sumber daya, dan tahan terhadap masalah siklus hidup Android.

```
// MyViewModel.kt
class MyViewModel : ViewModel() {
    // Data yang akan bertahan dari perubahan konfigurasi
    val userScore = MutableLiveData<Int>(0)

    fun incrementScore() {
        userScore.value = (userScore.value ?: 0) + 1
    }
}

// Cara mendapatkan instance ViewModel di Activity/Fragment:
// private val viewModel: MyViewModel by viewModels()
// atau: private val viewModel by activityViewModels() untuk berbagi ViewModel antar Fragment
```

💡 **Fun Fact:** Tahukah kamu, metode `onCleared()` pada ViewModel akan dipanggil ketika ViewModel tidak lagi digunakan dan akan dihancurkan? Ini adalah tempat yang tepat untuk membersihkan sumber daya seperti langganan RxJava atau Coroutine Scope untuk mencegah kebocoran memori.
