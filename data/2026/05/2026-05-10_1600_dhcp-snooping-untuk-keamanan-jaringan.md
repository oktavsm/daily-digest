## 🌐 Networking Concept: DHCP Snooping untuk Keamanan Jaringan

**Category:** Security
**TL;DR:** Melindungi jaringan dari server DHCP palsu dan serangan MAC/IP spoofing dengan memverifikasi pesan DHCP pada switch Layer 2.

Selamat pagi, mahasiswa/i. Hari ini, kita akan menyelami sebuah konsep keamanan jaringan Layer 2 yang sangat krusial, yaitu DHCP Snooping. Di era di mana perangkat terhubung ke jaringan secara dinamis, protokol DHCP memegang peran sentral dalam mendistribusikan alamat IP. Namun, kerentanan muncul jika ada pihak tidak bertanggung jawab memasang server DHCP palsu (rogue DHCP server) di jaringan kita. Server palsu ini dapat memberikan konfigurasi IP yang salah, mengarahkan trafik ke gateway yang salah, atau bahkan melakukan man-in-the-middle attack, menyebabkan gangguan serius pada operasional jaringan.

DHCP Snooping bekerja di switch Layer 2 untuk memverifikasi keabsahan pesan DHCP yang melewati switch tersebut. Konsep utamanya adalah membedakan port 'trusted' dan 'untrusted'. Port 'trusted' adalah port yang terhubung ke server DHCP yang sah (atau ke switch/router lain yang menuju ke server DHCP sah), di mana switch akan mengizinkan semua jenis pesan DHCP. Sebaliknya, port 'untrusted' adalah port yang terhubung ke perangkat pengguna akhir, di mana switch hanya akan mengizinkan pesan DHCP request dan reject, serta memblokir pesan DHCP server seperti offer, ack, dan NAK yang berasal dari port tersebut. Switch juga membangun 'DHCP Snooping Binding Database' yang berisi alamat MAC, IP, lease time, dan VLAN dari perangkat yang berhasil mendapatkan IP dari server DHCP sah.

Dengan mekanisme ini, DHCP Snooping secara efektif mencegah server DHCP palsu untuk berfungsi di jaringan, karena pesan 'offer' dari server palsu yang terhubung ke port 'untrusted' akan diblokir. Lebih dari itu, database binding yang dibangun oleh DHCP Snooping ini menjadi fondasi penting untuk fitur keamanan Layer 2 lainnya. Misalnya, fitur Dynamic ARP Inspection (DAI) dapat menggunakan database ini untuk memvalidasi permintaan ARP, dan IP Source Guard dapat memastikan bahwa perangkat hanya menggunakan alamat IP yang telah dialokasikan untuknya, sehingga mencegah spoofing alamat IP dan MAC.

Dalam simulasi Packet Tracer, Anda akan mengkonfigurasi switch dengan mengaktifkan DHCP Snooping secara global dan kemudian menentukan port mana yang harus menjadi 'trusted'. Biasanya, port yang mengarah ke server DHCP asli atau ke uplink menuju core switch akan diatur sebagai trusted. Sementara port akses ke end-devices secara default akan diperlakukan sebagai untrusted. Dengan penyiapan sederhana ini, Anda sudah dapat mengamati bagaimana sebuah server DHCP palsu yang terhubung ke port untrusted gagal mendistribusikan alamat IP, dan bagaimana klien hanya mendapatkan IP dari server DHCP yang sah.

```
interface GigabitEthernet0/1
 ip dhcp snooping trust
```

💡 **Fun Fact:** DHCP Snooping adalah fondasi untuk fitur keamanan Layer 2 lainnya seperti Dynamic ARP Inspection (DAI) dan IP Source Guard, yang juga mengandalkan database binding-nya untuk memverifikasi integritas trafik.
