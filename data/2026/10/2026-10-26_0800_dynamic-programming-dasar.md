## ⚡ Competitive Programming Concept: Dynamic Programming Dasar

**Category:** DP
**TL;DR:** Dynamic Programming adalah teknik optimisasi yang menyelesaikan masalah dengan memecahnya menjadi sub-masalah yang lebih kecil dan menyimpan hasil dari sub-masalah tersebut untuk menghindari komputasi berulang.

Dynamic Programming (DP) adalah metode yang kuat untuk memecahkan masalah optimasi dengan memanfaatkan dua properti kunci: *overlapping subproblems* dan *optimal substructure*. Overlapping subproblems berarti masalah yang sama muncul berulang kali sebagai sub-masalah, sedangkan optimal substructure berarti solusi optimal dari masalah besar dapat dibangun dari solusi optimal sub-masalahnya. Daripada menghitung ulang solusi untuk setiap sub-masalah yang sama, DP menyimpan hasil sub-masalah tersebut, seringkali dalam array atau hash map, sehingga dapat diambil langsung saat dibutuhkan.

Ada dua pendekatan utama dalam Dynamic Programming: Top-Down (Memoization) dan Bottom-Up (Tabulation). Pendekatan Top-Down dimulai dari masalah utama dan secara rekursif memecahnya menjadi sub-masalah, menyimpan hasilnya di cache (memo) saat pertama kali dihitung. Jika sub-masalah yang sama muncul lagi, hasilnya diambil langsung dari cache. Sebaliknya, pendekatan Bottom-Up dimulai dari sub-masalah terkecil yang diketahui solusinya, lalu secara iteratif membangun solusi untuk sub-masalah yang lebih besar hingga mencapai solusi masalah utama.

Untuk merancang solusi DP, langkah pertama adalah mendefinisikan "state" dari DP, yaitu parameter yang mengidentifikasi sub-masalah secara unik. Kemudian, tentukan "relasi transisi" atau rekurensi, yaitu bagaimana solusi untuk state saat ini dapat dihitung dari solusi state sebelumnya. Misalnya, pada masalah menghitung deret Fibonacci, `dp[i]` bisa didefinisikan sebagai bilangan Fibonacci ke-i, dengan relasi transisi `dp[i] = dp[i-1] + dp[i-2]`. Contoh masalah umum lainnya yang sering menggunakan DP meliputi Knapsack Problem, Longest Common Subsequence (LCS), dan penghitungan jumlah jalur di grid.

Kompleksitas waktu dari solusi DP umumnya ditentukan oleh jumlah state yang ada dikalikan dengan waktu yang dibutuhkan untuk menghitung setiap state dari state sebelumnya. Untuk masalah Fibonacci, kita memiliki `N` state (`dp[0]` hingga `dp[N]`), dan setiap state membutuhkan waktu `O(1)` untuk dihitung (penjumlahan dua bilangan). Jadi, total kompleksitas waktu adalah `O(N) * O(1) = O(N)`. Penting untuk menganalisis jumlah state dan kompleksitas transisi untuk memahami performa solusi DP.

```
#include <vector>
#include <iostream>

// Fungsi untuk menghitung bilangan Fibonacci ke-n menggunakan DP Bottom-Up
long long fibonacci_dp(int n) {
    if (n <= 1) return n;
    std::vector<long long> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; ++i) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    return dp[n];
}
```

💡 **Fun Fact:** Nama "Dynamic Programming" diciptakan oleh Richard Bellman pada tahun 1950-an. Ia memilih kata "Dynamic" untuk menunjukkan sifat *time-varying* dari proses dan "Programming" yang saat itu merujuk pada "planning" atau "tabulating" dalam konteks militer, bukan pemrograman komputer seperti yang kita kenal sekarang.
