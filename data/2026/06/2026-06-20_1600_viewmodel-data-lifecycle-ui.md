## 🤖 Android Concept: ViewModel: Data & Lifecycle UI

**Category:** Architecture
**TL;DR:** ViewModel adalah komponen Jetpack yang menyimpan dan mengelola data UI agar tetap utuh saat terjadi perubahan konfigurasi seperti rotasi layar, dan independen dari lifecycle Activity/Fragment.

Sebagai developer Android, salah satu tantangan awal yang sering kita hadapi adalah bagaimana menjaga data tampilan (UI data) tetap utuh saat terjadi perubahan konfigurasi pada perangkat, seperti rotasi layar. Tanpa penanganan yang tepat, setiap kali Activity atau Fragment dihancurkan dan dibuat ulang (misalnya, saat rotasi), semua data yang telah kita tampilkan atau proses di dalamnya akan hilang. Di sinilah ViewModel hadir sebagai solusi elegan dari pustaka Jetpack.

ViewModel didesain untuk menyimpan dan mengelola data yang terkait dengan UI secara lifecycle-aware. Ini berarti ViewModel tidak akan dihancurkan saat Activity atau Fragment dihancurkan karena perubahan konfigurasi, seperti rotasi layar atau perubahan bahasa. Sebaliknya, ViewModel akan tetap hidup selama cakupan lifecycle-nya (misalnya, sampai Activity benar-benar selesai/dimatikan oleh sistem), dan data yang disimpannya akan tetap tersedia untuk instance Activity/Fragment yang baru dibuat.

Untuk mengimplementasikan ViewModel, kita cukup membuat kelas Kotlin yang mewarisi `androidx.lifecycle.ViewModel`. Di dalam ViewModel ini, kita bisa mendefinisikan variabel atau fungsi untuk menyimpan dan memproses data UI. Kemudian, di dalam Activity atau Fragment, kita bisa mendapatkan instance ViewModel menggunakan delegasi properti `by viewModels()` (untuk Activity) atau `by activityViewModels()`/`by viewModels()` (untuk Fragment), yang memastikan ViewModel yang sama akan digunakan kembali saat Activity/Fragment dibuat ulang.

Penggunaan ViewModel membantu kita memisahkan tanggung jawab antara logika UI (di Activity/Fragment) dan logika bisnis serta penyimpanan data (di ViewModel), yang dikenal sebagai prinsip Separation of Concerns. Ini membuat kode lebih bersih, mudah diuji, dan lebih mudah dikelola. ViewModel juga sering digunakan bersama dengan `LiveData` atau `StateFlow` untuk secara reaktif mengamati perubahan data dan memperbarui UI secara otomatis.

```
import androidx.lifecycle.ViewModel
import androidx.activity.viewModels
import androidx.appcompat.app.AppCompatActivity

// 1. Definisikan ViewModel Anda
class MyCounterViewModel : ViewModel() {
    var count: Int = 0
    fun increment() { count++ }
}

// 2. Gunakan di Activity Anda
class MainActivity : AppCompatActivity() {
    private val viewModel: MyCounterViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // Sekarang 'viewModel.count' akan tetap sama bahkan setelah rotasi layar!
        // Tampilkan viewModel.count di UI
        // viewModel.increment()
    }
}
```

💡 **Fun Fact:** Sebelum ViewModel diperkenalkan, pengembang Android sering menggunakan `onRetainNonConfigurationInstance()` atau metode manual lainnya yang lebih kompleks untuk menyimpan data saat rotasi layar, yang seringkali rentan terhadap kesalahan dan kebocoran memori.
