## 🌐 Networking Concept: IP SLA & PBR untuk Redundansi Cerdas

**Category:** Routing
**TL;DR:** Pelajari bagaimana IP Service Level Agreement (SLA) dapat bekerja sama dengan Policy-Based Routing (PBR) untuk menciptakan failover jalur jaringan yang cerdas dan otomatis berdasarkan performa link, bukan hanya ketersediaan.

Dalam dunia jaringan yang dinamis, keputusan routing tidak selalu sesederhana memilih jalur terpendek. Bagaimana jika jalur terpendek memiliki latensi tinggi atau mengalami degradasi performa? Bagaimana jika kita ingin mengarahkan lalu lintas tertentu melalui link cadangan hanya ketika link utama benar-benar bermasalah, bukan hanya berdasarkan metrik routing standar? Di sinilah kombinasi IP Service Level Agreement (SLA) dan Policy-Based Routing (PBR) menjadi sangat kuat. IP SLA adalah fitur pada router Cisco yang memungkinkan kita memantau performa jaringan secara aktif dengan mengirimkan traffic probe seperti ICMP echo, UDP jitter, atau HTTP request ke tujuan tertentu. Router akan mengumpulkan statistik seperti round-trip time (RTT), packet loss, dan ketersediaan, serta dapat menentukan status operasional dari sebuah operasi SLA (up/down).

Policy-Based Routing (PBR) adalah mekanisme routing yang lebih canggih daripada routing tabel standar. Alih-alih hanya membuat keputusan routing berdasarkan alamat IP tujuan, PBR memungkinkan administrator jaringan untuk menentukan kriteria yang lebih spesifik, seperti alamat IP sumber, port TCP/UDP, atau bahkan ukuran paket, untuk memaksa lalu lintas tertentu mengikuti jalur yang berbeda dari yang ada di tabel routing. Ini memberikan fleksibilitas luar biasa untuk mengimplementasikan kebijakan lalu lintas yang sangat spesifik, misalnya mengarahkan lalu lintas web keluar melalui ISP A, sementara lalu lintas suara melalui ISP B, atau bahkan memprioritaskan lalu lintas penting.

Ketika IP SLA dan PBR digabungkan, kita mendapatkan solusi redundansi yang jauh lebih cerdas. Bayangkan sebuah skenario di mana perusahaan memiliki dua koneksi Internet, satu sebagai jalur utama (primary) dan satu sebagai jalur cadangan (backup). Dengan IP SLA, kita dapat mengkonfigurasi router untuk terus-menerus memantau kesehatan jalur utama dengan mengirimkan ping ke server di Internet melalui jalur tersebut. Jika operasi IP SLA mendeteksi bahwa jalur utama gagal (misalnya, tidak ada balasan ping), statusnya akan berubah menjadi 'down'. PBR kemudian dapat dikonfigurasi untuk memanfaatkan status ini.

Dengan PBR yang dikaitkan dengan status IP SLA, kita dapat membuat kebijakan: "Jika jalur utama (yang dimonitor oleh IP SLA ID 1) berfungsi, arahkan semua lalu lintas keluar melalui jalur utama. Tetapi, jika jalur utama gagal (IP SLA ID 1 down), ubah jalur semua lalu lintas keluar untuk menggunakan jalur cadangan." Ini menciptakan mekanisme failover otomatis yang dinamis dan proaktif, memastikan bahwa konektivitas jaringan tetap terjaga dengan intervensi manual minimal. Di Cisco Packet Tracer, konsep ini dapat disimulasikan dengan mengkonfigurasi dua router (masing-masing mewakili koneksi ke ISP yang berbeda) dan menggunakan IP SLA untuk memantau reachability melalui satu jalur, kemudian menggunakan PBR untuk mengalihkan lalu lintas jika jalur tersebut gagal.

```
set ip next-hop verify-availability 1 track 10
```

💡 **Fun Fact:** IP SLA tidak hanya digunakan untuk failover! Fitur ini juga sering dimanfaatkan untuk memantau kualitas layanan (QoS) atau Service Level Agreements (SLA) dengan penyedia layanan, memberikan data objektif tentang performa jaringan dari sudut pandang router Anda.
