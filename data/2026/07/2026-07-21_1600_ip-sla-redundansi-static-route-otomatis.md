## 🌐 Networking Concept: IP SLA Redundansi Static Route Otomatis

**Category:** Routing
**TL;DR:** Menggunakan IP Service Level Agreement (SLA) untuk memantau konektivitas dan secara otomatis beralih antar static route jika jalur utama gagal, memastikan redundansi dan ketersediaan tinggi.

Dalam skenario jaringan yang realistis, mengandalkan satu jalur static route saja sangat berisiko. Jika jalur utama putus atau next-hop tidak dapat dijangkau, lalu lintas yang seharusnya melewati rute tersebut akan mengalami blackhole karena router tidak memiliki mekanisme bawaan untuk mendeteksi kegagalan tersebut dan beralih ke jalur cadangan secara otomatis. Inilah mengapa kita memerlukan solusi yang lebih cerdas untuk static route.

IP Service Level Agreement (SLA) adalah fitur Cisco IOS yang memungkinkan perangkat jaringan untuk secara proaktif memantau kinerja atau ketersediaan koneksi jaringan. Kita dapat mengkonfigurasi IP SLA untuk melakukan berbagai jenis operasi, seperti mengirimkan ICMP echo (ping) ke alamat IP tertentu secara berkala. Jika operasi IP SLA tersebut berhasil, ini menandakan bahwa jalur konektivitas kita masih aktif.

Output dari operasi IP SLA dapat dihubungkan ke sebuah "tracking object". Tracking object ini kemudian akan berubah status menjadi 'up' atau 'down' berdasarkan keberhasilan atau kegagalan operasi IP SLA yang dipantau. Intinya, tracking object menjadi indikator kesehatan jalur jaringan yang spesifik. Objek pelacak inilah yang akan kita gunakan untuk mengontrol status static route.

Untuk mencapai redundansi otomatis, kita akan mengkonfigurasi dua static route ke tujuan yang sama: satu sebagai jalur utama dan satu sebagai jalur cadangan (sering disebut 'floating static route'). Jalur utama akan memiliki Administrative Distance (AD) yang lebih rendah dan akan terikat ke tracking object. Jika tracking object mendeteksi kegagalan (misalnya, ping gagal), jalur utama akan secara otomatis dihapus dari tabel routing. Router kemudian akan mengaktifkan jalur cadangan dengan AD yang lebih tinggi, yang sebelumnya tidak aktif karena AD-nya lebih besar, sehingga lalu lintas dialihkan ke jalur alternatif secara transparan. Ini memastikan kontinuitas layanan bahkan saat terjadi kegagalan pada jalur utama.

```
ip sla 1
 icmp-echo 192.168.1.1 source-interface GigabitEthernet0/0
 frequency 5
ip sla schedule 1 life forever start-time now
track 1 ip sla 1 reachability
ip route 0.0.0.0 0.0.0.0 10.0.0.1 100 track 1
ip route 0.0.0.0 0.0.0.0 10.0.0.5 150
```

💡 **Fun Fact:** Fitur IP SLA tidak hanya terbatas pada ICMP echo; ia juga dapat memantau protokol lain seperti HTTP, FTP, DNS, TCP connect, bahkan Voice over IP (VoIP) untuk mendapatkan metrik kinerja yang lebih mendalam, tidak hanya sekedar reachability.
