## 🤖 Android Concept: Memahami Activity: Jantung Aplikasi

**Category:** Architecture
**TL;DR:** Activity adalah komponen dasar aplikasi Android yang menyediakan layar tunggal untuk berinteraksi dengan pengguna.

Setiap kali Anda melihat layar di aplikasi Android, kemungkinan besar itu diwakili oleh sebuah Activity. Activity adalah komponen fundamental yang berfungsi sebagai titik masuk utama untuk interaksi pengguna, menyediakan jendela di mana antarmuka pengguna (UI) aplikasi Anda digambar. Bayangkan Activity sebagai satu halaman di buku digital Anda; setiap halaman baru adalah Activity yang berbeda, memungkinkan pengguna untuk menavigasi melalui fungsionalitas yang berbeda dari aplikasi.

Activity memiliki siklus hidup (lifecycle) yang terdefinisi dengan baik, mulai dari dibuat (`onCreate`), terlihat (`onStart`), bisa berinteraksi (`onResume`), hingga dihancurkan (`onDestroy`). Memahami lifecycle ini sangat penting untuk mengelola sumber daya dan perilaku aplikasi Anda dengan benar, misalnya, kapan menyimpan data atau menghentikan proses yang mahal. Metode `onCreate()` adalah tempat paling umum untuk melakukan inisialisasi awal, seperti mengaitkan layout XML dengan Activity menggunakan `setContentView()`.

Untuk membuat Activity baru, Anda cukup membuat kelas Kotlin yang mewarisi `AppCompatActivity` dan mengimplementasikan metode `onCreate()`. Selain itu, setiap Activity harus dideklarasikan dalam file `AndroidManifest.xml` agar sistem Android dapat mengenalinya dan meluncurkannya. Deklarasi ini juga biasanya menentukan Activity mana yang akan menjadi titik peluncuran utama aplikasi Anda (menggunakan `intent-filter` dengan `MAIN` dan `LAUNCHER`).

```
package com.example.myfirstapp

import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main) // Mengaitkan layout XML
    }
}
```

💡 **Fun Fact:** Pada versi awal Android (sebelum era modern seperti Jetpack Compose), Activity seringkali menjadi "God Object" yang menampung terlalu banyak logika UI dan bisnis, yang kemudian melahirkan pola arsitektur seperti MVP, MVVM, dan MVI untuk memisahkan tanggung jawab.
